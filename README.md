# המדף · ניהול מלאי ואירועים

מערכת לניהול מלאי של סטודיו לעיצוב שולחנות חתונה: ספרים, פמוטים, אגרטלים, נרות וכל קישוט אחר.
המערכת בנויה סביב אירועים: משייכים ציוד לחתונה לפי תאריך, רואים מה פנוי, ובסיום האירוע רושמים מה חזר, מה נשבר, מה אבד, מה נצרך ומה נמכר.

## מה יש במערכת

- **מלאי**: פריטים עם תמונה, קטגוריה, מיקום במחסן, ספק, עלות, מחיר מכירה ווריאנטים (צבע, מידה). חיפוש, סינון לפי קטגוריה, ובדיקת זמינות בתאריך מסוים.
- **אירועים**: שריון ציוד לתאריכי האירוע, התראה על חוסר כששני אירועים חופפים, רשימת ציוד להדפסה, שכפול אירוע, וסגירת אירוע עם רישום של מה שלא חזר.
- **לוח שנה**: תצוגה חודשית של האירועים, עם סימון של אירועים שחסר להם ציוד.
- **סטים לשולחן**: מגדירים פעם אחת מה יש על שולחן, ובאירוע בוחרים סט ומספר שולחנות. הכמויות מחושבות לבד.
- **מצב אריזה**: צ'קליסט לנייד בזמן ההעמסה ושוב בזמן ההחזרה, מסודר לפי מיקום במחסן. הסימונים נשמרים ומשותפים לכל הצוות.
- **ימי ניקוי**: לכל פריט אפשר להגדיר כמה ימים אחרי אירוע הוא לא פנוי (כביסה, ניקוי).
- **רשימת קניות**: חוסרים לאירועים ומלאי נמוך מרוכזים לפי ספק, עם שליחה בוואטסאפ וסימון "התקבל" שמעדכן את המלאי.
- **ייבוא מאקסל**: העלאת קובץ xlsx או CSV, או הדבקת תאים ישירות מהגיליון, עם תצוגה מקדימה לפני הייבוא.
- **מדבקות QR**: מדבקה לכל פריט להדפסה. סריקה במצלמת הטלפון פותחת את עמוד הפריט.
- **שני סוגי פריטים**: "חוזר מהאירוע" (יוצא וחוזר למחסן) ו"מתכלה" (נרות וכדומה, שנצרכים או נמכרים).
- **עדכון מלאי ידני**: הוספה, נצרך, נמכר, נשבר, אבד ותיקון ספירה, עם היסטוריה מלאה לכל פריט.
- **ספקים**, **דוחות** (רכישות, מכירות, פחת, הפריטים המבוקשים, שווי מלאי) ו**התראות מלאי נמוך**.
- **התאמה אישית**: קטגוריות וצבעים משלכן, ושדות נוספים לכל פריט (סגנון, מידות, חומר).
- **ייצוא** לאקסל (CSV) וגיבוי מלא (JSON).
- עברית מלאה מימין לשמאל, מותאם לנייד ולמחשב.

## הרצה מקומית

דרוש [Node.js](https://nodejs.org) בגרסה 22 ומעלה.

```bash
npm install
npm run dev
```

בלי הגדרת Supabase המערכת עולה ב**מצב הדגמה**: היא נטענת עם נתוני דוגמה ושומרת הכול בדפדפן הזה בלבד. זה מספיק כדי לבחון את הממשק והלוגיקה.

פקודות נוספות:

| פקודה | מה היא עושה |
|---|---|
| `npm test` | בדיקות יחידה של לוגיקת המלאי והזמינות |
| `npm run build` | בדיקת טיפוסים ובניית גרסת הפצה לתיקיית `dist` |
| `npm run preview` | הרצה מקומית של גרסת ההפצה |

## חיבור לענן (Supabase)

כדי שכמה אנשים יעבדו על אותו מלאי מכמה מכשירים:

1. פותחים חשבון חינמי ב-[supabase.com](https://supabase.com) ויוצרים פרויקט חדש.
2. ב-SQL Editor מדביקים את התוכן של [`supabase/schema.sql`](supabase/schema.sql) ומריצים. הקובץ יוצר את הטבלאות, ההרשאות, הסנכרון בזמן אמת ואחסון התמונות.
3. ב-Authentication > Users יוצרים משתמש (אימייל וסיסמה) לכל מי שצריכה גישה. מומלץ לכבות הרשמה חופשית תחת Authentication > Sign In / Providers.
4. מצרפים כל משתמש לצוות. ב-SQL Editor מריצים, עם האימייל המתאים:

   ```sql
   insert into public.team_members (user_id)
   select id from auth.users where email = 'name@example.com';
   ```

5. מעתיקים את `.env.example` לקובץ `.env.local` וממלאים את כתובת הפרויקט ואת המפתח הציבורי (publishable key) מתוך Project Settings > API.
6. מריצים שוב `npm run dev`. יופיע מסך כניסה במקום מצב ההדגמה.

**אבטחה:** האתר והמפתח הציבורי גלויים לכולם, וזה תקין. הגישה לנתונים מוגבלת בבסיס הנתונים עצמו (Row Level Security): רק משתמש מחובר שמופיע בטבלת `team_members` יכול לקרוא או לשנות משהו. את המפתח הסודי (secret / service_role) לא שמים בשום מקום בפרויקט הזה.

## העלאה ל-GitHub Pages

הפריסה אוטומטית בכל push לענף `main`, דרך [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml).

1. ב-Settings > Pages של המאגר בוחרים Source: **GitHub Actions**.
2. ב-Settings > Secrets and variables > Actions > **Variables** מוסיפים את `VITE_SUPABASE_URL` ואת `VITE_SUPABASE_KEY`.
3. דוחפים ל-`main`. אחרי דקה או שתיים האתר זמין בכתובת ה-Pages של המאגר.

בלי שני המשתנים האתר יעלה במצב הדגמה.

## מבנה הפרויקט

```
src/
  lib/
    types.ts            מבנה הנתונים
    db.ts               פעולות על בסיס הנתונים בזיכרון (כולל מחיקה מדורגת)
    stock.ts            חישובי מלאי, זמינות, חוסרים וסגירת אירוע
    importItems.ts      תכנון ייבוא מגיליון (כולל csv.ts לקריאת הקובץ)
    shopping.ts         רשימת הקניות לפי ספק
    *.test.ts           בדיקות ללוגיקה
    backend.ts          שכבת האחסון: דפדפן מקומי או ענן
    supabaseBackend.ts  החיבור ל-Supabase (נטען רק כשמוגדר)
    store.tsx           מצב האפליקציה ושמירה
    seed.ts             נתוני הדוגמה
  components/           טפסים, חלונות ורכיבי ממשק
  pages/                לוח בקרה, מלאי, סטים, מדבקות, אירועים, אריזה, ספקים, קניות, דוחות, הגדרות
supabase/schema.sql     סכמת בסיס הנתונים וההרשאות
```

## איך המלאי מחושב

- **בבעלות**: סכום כל תנועות המלאי של הפריט (יומן שרק מוסיפים אליו).
- **בחוץ**: מה ששויך לאירועים שסומנו "יצא" ועדיין לא נסגרו.
- **במחסן**: בבעלות פחות בחוץ.
- **פנוי בתאריך**: בבעלות פחות מה שמשוריין לאירועים פתוחים שחופפים לתאריך, כולל ימי הניקוי של הפריט. פריט מתכלה ששויך לאירוע מוקדם יותר נחשב כבר לא זמין, כי הוא לא חוזר.

## טכנולוגיות

React, TypeScript, Vite, Tailwind CSS, Supabase (Postgres, Auth, Realtime, Storage), Vitest.
